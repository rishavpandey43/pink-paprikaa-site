## Deviation: two more `.prettierignore` entries

After Step 2, `nx format:check` still failed. It flagged 11 files that are unchanged since the initial commit:
`.agents/skills/{monitor-ci/SKILL.md, monitor-ci/scripts/ci-poll-decide.mjs, monitor-ci/scripts/ci-state-update.mjs, nx-import/references/{ESLINT,JEST,VITE}.md, nx-workspace/SKILL.md}` and `.github/skills/{nx-import/references/{ESLINT,JEST,VITE}.md, nx-workspace/SKILL.md}`. These files were already failing at Step 1. `tail -3` only showed the zip-files lines, so they were hidden.

**Root cause:** this checkout is a fresh clone of `github.com/rishavpandey43/pink-paprikaa-site`. Local `main` (`e57951d`, "docs: Add PIXEL.md…") is the **live site's history**, with no shared history with `feat/design-system`. `git merge-base main HEAD` fails. When that happens, Nx's `getMergeBase` falls back to the raw `main` ref, and `git diff main HEAD` lists nearly every file. So `nx format:check` in its default (affected) mode checks the whole workspace. These Nx-generated agent skills (arch spec §18: "Kept `.agents/skills/` and `.github/skills/`, which hold the Nx skills") were never formatted by Prettier.

**Fix:** I followed the spec's existing precedent for machine-generated files (`pnpm-lock.yaml`) and added this to `.prettierignore` in commit 1:

```
# Nx-generated agent skills (arch spec §18); regenerated by Nx, never hand-formatted
.agents/skills/
.github/skills/
```

I chose ignoring over `prettier --write` because Nx regenerates these files, so a reformat would be overwritten and fail again. The commit body records the reason.
