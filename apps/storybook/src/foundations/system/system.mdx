# System (sx)

Every component takes one style-override prop, `sx`, in the direction MUI v7 took: a single typed
object instead of a growing list of one-off props. Ours is stricter than MUI's. Values are **tokens
only**: a spacing step, a named radius, a surface colour. A raw length, a hex or a class name is a
type error, so an override can never leave the design system.

```tsx
<Box sx={{ p: 6, radius: "lg", bg: "soft" }} />
```

Each family below renders live, with the exact object printed beside it.

## Spacing

steps of the spacing scale; margins also take `"auto"`.

## Colour

`bg` paints **light grounds only**: `page`, `page-alt`, `card`, `sunken`, `soft`. A brand or ink ground
changes the text colour of everything inside it, which the surface system does through
`data-surface`, so those are set with the component's `surface` prop, never with `sx.bg`. `color` picks a
text colour.

## Rules

- **`className` wins.** `sx` is applied before `className`, so a class a caller passes overrides the
  same `sx` key. Reach for `sx` first and `className` only for what `sx` cannot say.
- **One object, the outermost element.** `sx` styles the component's root (or its outermost slot).
- **CSS budget.** Responsive classes are assembled at runtime, so the stylesheet declares the full
  set once. That whole system may add at most 20 KB gzip to the built CSS.
- **Beyond `sx`.** Anything it cannot express (nested selectors, state styles) belongs in a
  component variant, not in an override.
